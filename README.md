# standoff-2-graphics
Появилась идея сделать при вводе пользователем скина сделать прверку на его существование в бд. Предлагается вариант поиска с помощью minHash, Lsh. Для больших множеств время поиска O(n²), для minhash O(n*k), где n - число скинов, k - количесвто хэшей для каждого скина. Так как сейчас ~2000 ск, а хэширование будет 1000 и с учтом расширения бд, сложность выходит меньше квадратичной. Для метода Монте-Карло (способа оценки какой-то величины с помощью случайных значений) нужны независимые случайные события, возникает лавинный эффект, когда любое небольшое изменение сильно меняет случаный результат, тк не существует алгоритма объективно генерирующего случайные числа, то это выход. Для sha-256 этот эффект подтвержден институтом стандартов США. Каждое слово можно расмотреть как множество, если сравнивать их как единичные элементы, то будет неточный результат, нужно много опытов, поэтому хэш-чисел 1000. Для того, чтобы сравнить похожесть множеств используют коэффициент Жаккара: Q = пересечение/объединение, если 1 - полное совпадение, 0 - нет совп. Получа.тся, что все элементы имют равный шанс дать минимальный хэш.
План:
1) Получаем названия всех скинов, делим их на триграммы, добавив доп символы.
2) Для каждой триграммы создаем 1000 хэш значений. Для генераций хэширующих функций - SHA256 с зерном. Зерно означает, что на вход такой всегда одинаковой функции(пусть h) подается h(n, seed), поэтому результат разный(число)
3) Для каждого соотвествия название: список чисел разрезаем на полосы(lsh), получаем название: числа(результат вычисления корзин)
4) Для всех скинов делаем один раз, храним либо с помощью picikies(cловарь), либо json. Первый способ занимает меньше места, но нечитаем
5) Получаем название, которое нужно найти в бд от пользователя, приводим к универсальному виду(пробелы, регистр). Обрабатываем его п.1-4.
6) Отбираем кандидатов, которые совпадают хотя бы по олному параметру, кладем в set и сравниваем кандидатов через цикл с зиначальным словом пользователя.
